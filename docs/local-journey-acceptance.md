# 双岗完整会话与异常恢复验收

执行 `bun --no-env-file run agent:local:journey`。仅离线合成数据，不读取真实凭证，不发供应商请求。产物在 `.cache/journey-acceptance/run-*/report.json`、`review.md`、`recovery.log`，绑定源码清单/摘要并保留子验收产物路径。

## 证据通道

1. 直接宿主混合会话，每岗独立临时profile：正常作答→新题→提示1→澄清→重启→提示2及第三次拒绝→合成音频分块上传/确认→辅助作答评分→再次规划→知识缺口收尾→报告/记忆→重启回执/事件重放→下一场记忆召回。hint repository为SQLite测试fixture，非正式实现。
2. 独立新profile辅助弃评，每岗一例：提示→缺证据澄清→再次不确定→弃评→报告null、记忆不新增。不得把它拼成混合会话的第三题。
3. 实际生产文字sidecar构建/stdio验收：现有accept-local-agent；从独立cwd启动、两岗会话/正式回执、重启/下一场记忆，默认确定性provider。
4. 单独构建注入式语音测试sidecar：实际Pi、私有凭证帧及stdio，供应商HTTP/凭证/音频全部合成；验证ASR/TTS/确认/账本。不是生产安装包或真实硬件。
5. 恢复专项：既有租约/候选过期、原子对账/回执、live任务恢复、进程生命周期、启动诊断、双岗澄清连续性测试。退出码、测试计数和日志摘要一并保存，失败不自动重跑。

## 结论与未通过项

`mechanismStatus`只表示这些离线动作/断言是否通过；`experienceStatus=needs-improvement`保留提前收尾问题。CLI退出0预留给完整体验通过，1为机制失败，2为执行完成但存在体验发现，不能将2当作供应商调用失败后重试。

当前开发内容的当前技能题源耗尽后，规划工具仅允许查询原规划技能，未自动选择其他技能就进入knowledge_gap。记录当时剩余时间、技能与其他技能未见草案题数，作为改进依据；数量不等于已经独立审核或全部可立即出题。后续修复该行为，应更新验收数据/预期并保留旧报告，不能把当前观察断言当作理想产品要求。

本次连续场景同时核验辅助来源在正式报告、记忆和候选提交门控保持一致，删除报告辅助标记须拒绝。正式提示repository、真人答案、独立审核、真实语音/设备、桌面与安装均不在“通过”范围。
