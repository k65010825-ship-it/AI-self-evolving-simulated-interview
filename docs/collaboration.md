# 协作与里程碑

交付日期：2026-12-19。三人共用一个 Bun workspace 仓库，分别负责桌面/前端、业务后端、Agent。需求以 [PRD](prd.md) 为准，联调先看 [接口文档](api.md)。

## 1. 模块分工

| 负责人 | 主要目录 | 对团队交付 |
| --- | --- | --- |
| 前端 | apps/desktop | Electron 壳、界面、录音/转写确认、报告与双曲线、安装包验证；审核 Web 前端题目 |
| 后端 | apps/api、packages/db、infra | 登录/归属、正式会话、任务与状态、持久数据、事件、策略版本、部署；审核 Java 题目 |
| Agent | apps/agent、knowledge、evals、experiments/pi-sdk | 规划、知识访问、评估、记忆召回、语音服务适配、反思与策略实验 |
| 共同维护 | packages/contracts、packages/interview-domain、docs | 跨端字段/状态、评分锚点、错误与契约、验收样例 |

目录分工不是禁止其他人修改；跨模块 PR 请对应负责人确认。Agent/RSI 的真实链路依赖三人协作，不能把全部工作集中给 Agent 同学。

## 2. GitHub 协作约定

- 每个功能使用独立分支，通过 PR 合并；PR 聚焦一个可验证增量。Codex 创建分支使用 codex/ 前缀。
- PR 写清“用户触发什么 → 行为发生什么变化 → 如何验证 → 已知限制”，附相关需求编号（如 3a/5b）。
- 跨端字段变更先改公共契约、请求/响应样例及文档；两端按同一约定并行，不复制各自私有 DTO 猜测联调。
- 修改生成器或 schema 后运行 openapi:generate；提交源码和生成的 openapi.yaml/tool-schemas.json，禁止只手改生成文件。
- bun.lock 是唯一依赖锁文件；只读安装用 --frozen-lockfile。依赖变更说明用途和兼容性，避免三人各自生成不同锁文件。
- 提交源码、文档与公开测试样例；不提交 node_modules、dist、.cache/.tools、.env、真实密钥、学生原始音频/简历或私人测试数据。当前 .gitignore 已覆盖常见本地生成目录，真实业务数据仍须额外审查。
- 真实模型/语音接入前共同确定供应商、凭证来源和预算。模型密钥仅在服务端配置，不能放进客户端安装包。

建议每个成员首次克隆后先运行 README 中的检查命令，再开始所属模块。自动化编码约定见根目录 AGENTS.md，Pi 接入规则见项目 Skill。

## 3. 合并前检查

文档改动：核对内容与代码是否一致、相对链接是否有效、目标能力是否错误写成已实现。文档-only PR 不强制重跑模型或数据库。

代码改动：根据变更运行相关测试；基础回归命令为 typecheck、test、pi:offline、check:knowledge、openapi:lint、desktop:build。GUI、语音、数据库和安装包需各自的实际验证，不能只依赖构建结果。

当前仓库尚未配置 GitHub CI/分支保护；上传后再由团队设置，不能假定远程已经执行检查。上传仓库、合并 PR 和部署均不是本文自动执行的动作。

## 5. 每周组会模板

建议 30 分钟：集成演示 10 分钟、指标和失败案例 10 分钟、下周任务和阻塞 10 分钟。

每次只记录：本周新增且已验证（需求编号/版本/复现步骤）、已实现但未验证（缺什么证据）、当前问题、下周负责人/日期/验收动作。重点跟踪两岗内容、状态规划、真工具/语音链路、复测配对数和 RSI 实验阶段。

如果延期，先压缩装饰、扩展工具、非核心题库数量；双岗、四类题、四项 Agent 能力、语音/情感、自动策略与真实对比仍是验收核心。
