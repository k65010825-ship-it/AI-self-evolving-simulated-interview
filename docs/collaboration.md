# 协作与里程碑

协作基线更新于 2026-11-16。先按[架构](architecture.md)区分“本地学生运行域”和“中央管理域”，再按[接口导航](api.md)接线。本文的任务表是待交付清单，不是完成记录；原型交接中旧云端面试 API 清单不再作为新客户端主流程。

## 1. 双端范围与本期边界

### 1.1 用户桌面应用

Electron 界面随包启动独立本地 Agent 子进程，通过 stdio RPC 通信；模型与语音供应商可以联网。一次面试的正式会话、答案、报告、记忆、任务、事件、预算与提交回执以本机 SQLite 为准，用户无需先把完整面试上传服务器才能继续。

| 原型页面 | 必须交付的业务能力 | 主要数据来源 |
| --- | --- | --- |
| 关卡 | Java 后端 / Web 前端选岗、练习目标、15—25 分钟时长 | 已安装岗位知识与本地历史 |
| 试炼 | 多轮题目、文字回答、录音→转写→确认提交、取消/收尾、恢复状态 | 本地宿主命令、任务与事件 |
| 战报 | 多维分数、亮点/不足、原文证据、练习建议；文字输入不虚构语音分 | 本地已提交报告 |
| 修炼 | 推荐资源、学习完成记录、同技能不同题复测 | 资源版本、本地练习与配对记录 |
| 进化 | 技能成长与教练策略变化分别展示，注明样本和版本 | 本地成长记录及实际采用的策略版本 |
| 面板 | 分岗位的掌握度、置信度、薄弱点与证据 | 本地记忆/画像视图 |

“小狐”、招式卡和技能树是交互包装。表情与结果提示由已校验的业务状态或 Evaluation 驱动，不能沿用原型中的回答长度/关键词模拟评分。桌面应用不内嵌管理员权限页面；原型 index.html 中残留的管理页面不作为学生入口。

### 1.2 网页管理端

管理端有独立 Web 页面和受鉴权保护的 HTTP API。“三中台”是同一管理应用中的三个业务模块，首版不拆成三个服务。

| 模块 | 本期交付 | 权限和验收边界 |
| --- | --- | --- |
| 监控中台 | Agent 行为指标、管理服务运行状态、已授权回传的用量/反馈与告警 | 只读；刷新、告警或查询不能触发模型调用、评测或策略修改 |
| 数据中台 | 知识、技术依据、资源索引、回答样本、评测样例、系统用量的分类与来源查询；开发/验证/最终集分组 | 最小数据管理，不建设通用 ETL 平台；真人/合成、自报/核实分别标记，同源变体不得跨组泄漏 |
| 评测中台 | 创建受控实验、查看运行状态、逐例结果、参数差异与达标结论、导出报告 | 调用 Agent 既有评测核心；模型调用须显式授权并限定预算；评测达标不等于正式发布 |
| 知识库审核 | 两岗预定义题目/rubric 的版本、结构检查、审核/驳回记录 | 管理 API 验证审核者身份及权限，绑定具体版本/内容摘要；draft 不因页面点击或文件声明自动成为正式 reviewed |
| 审计日志 | 审核、样本入组、评测、授权及发布/回退相关记录 | 记录操作者、对象版本、时间、操作结果；不伪造管理员身份或历史成功记录 |

管理端初期沿用 `deploymentStatus = not_published`。发布/回退按钮保持禁用，直到受鉴权的发布协调器具备版本 CAS、幂等、事务审计、失败回退及客户端采用验证；评测模块本身没有发布权。云端 champion、客户端已下载版本和当前面试固定的策略版本必须分开显示，不能把“候选达标”写成“所有客户端已启用”。

原型的 68%、12 对、80 题、已审核数量、时延和进化时间线均不是当前验收证据。监控展示须注明数据范围、来源、时间窗及适用的分子/分母；样本不足显示不足，不能补成演示收益。现有校准就绪需至少 8 个合格配对、至少 2 名学生，并满足岗位/技能/难度/量规/来源等规则；不只按同岗总条数凑门槛，也不能把该门槛当所有策略实验的统一通过标准。

## 2. 数据所有权与两条通信链路

| 数据/动作 | 权威位置或执行方 | 另一端的边界 |
| --- | --- | --- |
| 统一账号、student/admin 角色、登录会话 | 管理服务/账号 API | 不把本地 profileId 当远程登录凭证；隐藏按钮不代替服务端鉴权 |
| 用户面试、报告、画像、跨会话记忆、任务、预算、回执 | 本地宿主及用户目录 SQLite | 管理端不能直接改用户本机正式记录，不重复维护一套远程面试主流程 |
| 团队题库、rubric、资源索引、审核决定及可分发版本 | 管理服务 | 桌面使用经过校验的版本化本地副本；离线可读，更新失败不覆盖可用版本 |
| 本地反思和个性化策略候选 | 本地 Agent 核心产候选，宿主控制提交 | 不自动等同全局实验、云端发布或真人效果 |
| 管理端数据集、实验任务/结果、审计与将来的正式发布记录 | 管理服务，复用 Agent 核心计算 | 不由网页或模型直接改库；与用户本地正式会话分开 |
| 学生反馈及评测样本回传 | 用户明确授权的上传/导入 | 首版按需上传最小样本或摘要，不自动同步全部会话、简历或原始音频 |

两条链路分别联调：

- **学生面试链路**：桌面渲染层 → 受限 preload → 主进程 → stdio → 本地宿主 → Agent 核心 → 网络供应商；本地宿主负责提交与恢复。
- **内容与管理链路**：网页管理端 → 管理 HTTP API → 管理数据库/实验执行器；桌面只通过明确的账号、内容版本查询/下载、授权回传等接口访问管理服务。

master 当前 PostgreSQL/Drizzle 仍是历史 44 表模型；feature/db 已提交管理 PG / 本地 SQLite 拆分，待 PR 集成。后端先核对新模型与既有本地宿主的字段、迁移和事务边界，新业务表/查询投影接入同一profile，local_*继续为权威；不把 packages/local-db 存在视为用户旧 profile 已迁移。不为了保留旧表让本地 Agent 改回远程执行；旧学生面试 HTTP 仅作回归，不能作为新桌面面试必经入口。

## 3. 三人分工与接手顺序

| 负责人 | 主责 | 对团队的交付 |
| --- | --- | --- |
| 前端 | 用户桌面与管理 Web 的界面；Electron 主进程接线、受限桥接、录音/播放与安装包 | 对接本地客户端 SDK 和管理 API；提供两端真实状态、加载/失败/恢复交互；不自行判分或授予 admin 权限 |
| 后端 | 管理 API/数据库、认证与权限、内容审核/版本分发、评测任务与审计；本地业务与数据层的接管/补缺 | 提供稳定查询视图和管理接口；接管本机数据迁移、正式提交/奖励的业务规则，复用现有协调器；与前端完成凭证和账号绑定联调 |
| Agent | 本地运行时/sidecar、Pi、规划、评分、知识工具、记忆召回、压缩与恢复、语音供应商适配、反思和评测核心 | 交付主进程 SDK/契约、候选结果及指标口径、评测函数与诊断；配合本地业务层和管理实验执行器接入，不实现管理员认证或桌面 UI |
| 共同维护 | packages/contracts、packages/interview-domain、knowledge、docs | 对齐跨端字段/状态、审核规则、数据来源、发布权限与验收样例；Java 内容由后端同学参与审核，Web 内容由前端同学参与审核 |

本仓库当前保留 `apps/api` 与旧试点；桌面源码已从 Agent 工作区删除。前端可以在自己的客户端工作区开发；管理 Web 的目录由前端在接入时确定，本文不声称已存在。Agent 工作不自动恢复或修改桌面工程。

本地正式提交、记忆、任务/事件、预算、stdio 与语音机制已有实现及不同层次的测试，后端先接管和验收，不按交接包“所有 uncommitted 结果都未落库”的旧描述重建。是否可交付仍须区分离线注入、真实模型、物理音频、管理鉴权、桌面安装及真人质量验证，不能以一次建表或 CLI 成功代替。

### 3.2 Agent 补齐与三人接线顺序

| 顺序 | Agent 交付 | 后端配合 | 前端接入与验收 |
| --- | --- | --- | --- |
| 1 | 本地会话/报告安全投影：澄清、弃评、逐轮反馈、原文证据、统一六技能目录 | 确认维度汇总与引用 DTO；现有四技能到目标六技能不篡改历史证据 | 两岗创建→作答/澄清/弃评→收尾→战报；表情区分运行状态与评分 |
| 2 | 结构化弱点/覆盖练习模式，受控分级提示与辅助状态 | 本地领取/扣币/奖励幂等与失败补偿，明确有效完成条件 | 显示提示次数/结果；重放不重复扣币，失败不显示成功 |
| 3 | 资源、学习/复测、画像趋势的本地 RPC，复用已有规则 | 本地持久化与 schema 适配；自报/核实区分 | 修炼→不同题复测→成长；重启保留记录，未出题不泄露题目 |
| 4 | 本地反思/指标投影、独立持久实验任务与候选回执 | 授权回传/导入、管理实验编排与只读查询 | 展示分子分母、版本/来源及失败；completed 不等于 published |
| 5 | 安装内容/策略包校验、固定会话版本、失败保留旧版 | 审核/发布记录、版本化 manifest/下载与审计 | 展示可用/已安装/当前会话采用版本；未验收发布保持禁用 |

每步先在 contracts 定义字段、错误、幂等与权限，再实现。新增 RPC 同步 local-agent-client 与本地协议；管理端 HTTP 单独定义，不把本地 RPC 改装为远程学生接口。核心函数已有不等于本地接线已完成，以上清单尚待实现验收。

## 4. 统一账号、轻量游戏化与数据回流

- 统一账号体系区分 `student` / `admin`；两端可共用认证服务，具体页面入口随桌面/网页呈现，不能把“一个账号体系”理解为“学生必须访问管理员页面”。
- 账号身份不替代本地宿主权限。登录/退出/换号与本地 profile 的绑定、旧数据归属及本地目录隔离由后端和前端先确定契约并验收；退出不自动删数据，换号不静默接管旧数据。账号过期影响受保护管理资源，不自动撤销已保存记录的本地读取权。
- 轻量 XP/金币按交接说明第 2/7 节纳入交付目标，替代其前文“仅视觉”的旧描述。本期先以本地 profile 持久化，不引入跨设备钱包或成绩同步；需要云端账号共享余额时另定唯一权威和同步契约，不能两边都加减。
- 默认规则集中配置：完成有效面试 `xp +100`；完成学习 `xp +30 / coins +20`；完成复测 `xp +100 / coins +50`；成功领取提示 `coins -1`；`level = floor(xp / 500) + 1`。原型其他 +180/+120 等数值仅为展示，不同时采用。
- 一次复测按复测规则结算，不叠加普通面试奖励；完成记录、奖励与扣币按业务操作幂等关联。余额不足明确拒绝，操作失败不重复扣费，无独立“加金币”接口。金币不等同真实模型调用预算，不扩大 LLM/ASR/TTS 授权。
- 提示功能由后端协调领取/扣币，Agent 提供受控内容，前端呈现；提示影响的回答须记录辅助状态，不能与无辅助回答直接混作独立评分或 RSI 改善样本。学习自报完成与核实证据分开保存，领取 XP 不证明掌握。
- 不做商城、排行榜、签到、每日任务、用户自定义题库或向量 RAG。知识审核针对团队维护内容；金币/小狐表情不能影响技术分数或审核权限。
- 用户凭证不进安装包、渲染层、普通 RPC、管理审计或用户数据库；主进程走已有凭证代理。若改用团队统一付费 Key，再单独约定服务端网关和限额，不把统一账号误当作已实现模型计费服务。

## 5. 契约、Git 与合并检查

- master 的 docs 仅保留产品/架构/协作、数据库、数据治理、产品验收及前端/后端所需接入契约，清单见[团队入口](README.md)。Pi/Harness、内部工具与算法、开发调试、旧试点和模块/批次验收文档只在feature/agent；不能整目录合回master。
- 同步master到feature/agent时保留该分支的内部文档；将来实现PR合回master时只带共享文档和必要代码，检查删除/重命名与生成物，避免内部文档重新混入主分支。

- 当前 Agent 实现集中在 `feature/agent`；`master` 先维护共同协作文档与稳定基线。Agent 代码、契约实现、测试和依赖在实现分支提交，`README.md`、`AGENTS.md`、`docs/` 的团队文档在主分支提交后同步到实现分支；不将文档合入视为实现已合入主分支。
- 推送前先 `git fetch origin`，将对应远程分支的新提交合入本地并解决冲突，检查后再同名推送。禁止用强制推送覆盖队友；共享文档先合 master，再由实现分支正常合入 master。当前 master 的旧桌面骨架不代表要在 Agent 分支恢复桌面源码。
- 跨端 schema 以 `packages/contracts` 为真值，业务状态规则在 `packages/interview-domain` 共享。新增接口先写清归属、输入/结果、状态、权限、幂等和错误样例，再并行开发。
- stdio 接口对照 [本地通信契约](local-runtime-api.md)，管理 HTTP 对照 [API 文档](api.md) 并增补管理契约；不能把 HTTP/SSE 的 request ID 和本地业务 operationId/jobId/事件序号混用。
- 现有主进程 SDK `@interview/local-agent-client` 可复用启动/请求/事件和凭证代理；前端 preload 只暴露具体业务方法，不暴露任意 request、文件路径、SQL 或 spawn。
- 每个功能独立分支/PR，描述具体触发、行为变化、验证与限制，附需求编号；跨模块修改由相应负责人确认。Codex 分支使用 `codex/` 前缀，不未经要求提交、推送或部署。
- `bun.lock` 为唯一锁文件；公开依赖变更说明用途。schema/生成器改动运行 `openapi:generate` 并提交对应生成文件，不只手改 YAML/JSON。
- 不提交 node_modules、dist、.cache、.env、真实 Key、原始音频、简历或私人评测数据。真实付费执行需明确供应商、凭证来源、请求/费用/时间上限；授权不因开新任务或重启自动续用。
- 文档-only 改动核对链接、边界和实现声明；不为改文档调用付费模型。行为变更运行相关测试，交付前运行 typecheck、test、pi:offline、check:knowledge、openapi:lint；数据库、网页、音频、安装包分别实测。
- 用户/管理员鉴权、跨账号隔离、发布/审核越权、重复奖励、重启恢复与预算未知状态进入联调清单。未实现接口保持明确未实现，不能返回 mock 成功冒充交付。
- GitHub CI/分支保护由团队在远程仓库设置并提供实际运行证据，不把本地检查或合并到 master 视作已运行远程 CI。

1. **本周完成内容**：本周新增、负责人、版本和复现步骤，不重复累计旧成果。
2. **当前项目状态**：桌面、本地宿主、管理 API、管理 Web 分开；已实现与已验收分开。
