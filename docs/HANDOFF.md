# AI 自进化模拟面试工作台 — 交接文档

> 历史原型归档：本文金币/扣币和云端学生会话主流程已废弃。当前规则为每道已发题最多2次有效提示、不扣金币；数据库迁移/repository由后端主责，全部Agent实现由Agent负责人维护。执行以[PRD](prd.md)、[协作](collaboration.md)及[数据库第8节交接清单](database.md#8-数据库负责人交接清单)为准。正文保留历史输入，不作为当前接口或已完成功能。

> 归档说明：本文由原型阶段交付，`index.html` / `admin.html` 原型未随本仓库提交。文中接口清单与产品决策作为需求输入参考；与 [PRD](prd.md)、[接口文档](api.md) 冲突时以后两者为准，游戏化数值与角色 scope 已落入[数据库设计](database.md)。
>
> 本文档用于向开发同学（尤其交给 Codex / 后端 API 同学 / Agent 同学）交接「用户端 + 管理端」的原型设计与接口改动需求。
> 阅读顺序：先看本文，再打开 `index.html`（用户端）和 `admin.html`（管理端）。

## 0. 一句话定位

这是一个**桌面客户端**（Electron），面向计算机专业学生，做 **AI 模拟面试**。核心卖点是**双闭环**：

1. **学生练习闭环**：选岗位 → 面试 → 报告 → 学习复测 → 成长记录。
2. **系统自进化闭环（RSI）**：系统用学生练习产生的数据，自动评测并进化「AI 面试官」的出题/追问策略。

系统最终**分为两套界面**：**用户端**（学生）+ **管理端**（管理员），通过「统一账号 + 角色 scope」区分。

## 1. 两端界面说明（对应两个 HTML）

### 1.1 用户端 — `index.html`

游戏化风格，虚拟人物「小狐」AI 面试官贯穿全程。底部「旅程导航」切换 6 个页面：

| 页面 | 游戏化包装 | 底层概念 |
|------|-----------|---------|
| 关卡 | 选 Boss 战场 | 岗位选择（Java 后端 / Web 前端，各 6 技能模块）|
| 试炼 | 回合制对战 | 面试进行中（问题 = 招式卡，回答 = 接招）|
| 战报 | 战斗结算 | 面试报告（分维评分 + 亮点/不足 + 练习建议）|
| 修炼 | 修炼场 | 学习资源 + 复测入口 |
| 进化 | 技能树 | 成长记录（技能掌握度历史 + 系统策略版本演进）|
| 面板 | 角色属性 | 个人画像（掌握度/置信度/证据）|

**试炼页核心交互**：面对面舞台（小狐在上、玩家在下），底部「行动菜单」三按钮：
- 🎤 语音回答（主行动，先转写 → 确认 → 再提交）
- ⌨ 文字回答（弹层输入）
- 💡 请求提示（消耗金币）

**小狐表情随回答质量变化**（原型里用「回答长度 + 关键词」模拟判定，真实接入后替换为后端 Evaluation 分数驱动）。

**注意**：原型里的 XP/等级/金币是**纯视觉隐喻**，不是真实功能；是否引入真实数值系统，产品层尚未定。

### 1.2 管理端 — `admin.html`

**不是传统后台**，而是支撑「Agent 自进化」的**三中台**：

| 中台 | 定位 | 页面核心 |
|------|------|---------|
| 📡 监控中台 | 观测引擎（只读）| Agent 行为指标 + 系统运行状态 + 学生反馈回流 + 告警流 |
| 🗄 数据中台 | 数据引擎 | 数据流管线 + 六类数据分类 + 评测集分组隔离 |
| ⚗ 评测中台 | 进化引擎 | 实验编排流（创建→跑评测→逐例核对→达标判定）+ 进化时间线 |
| 📖 知识库审核 | 治理 | 题库审核队列（draft → reviewed）|
| 📋 审计日志 | 审计 | 全链路操作轨迹 |

**三条硬红线**（原型里已明确标注，实现时必须遵守）：
1. **监控中台只读**，不触发任何策略变更。
2. **评测中台当前无发布权**：所有评测产出 `deploymentStatus = not_published`，正式 champion 存储与事务启用/回退待业务 API 实现。
3. **数据不足不伪造样本**：自动候选门槛「同岗位 ≥8 合格配对」，不足则跳过。

## 2. 关键产品决策（已拍板）

1. **认证方案**：统一账号体系 + 角色 scope（`student` / `admin` 两种 role），登录后按 role 区分可访问接口。**不搞两套独立登录入口。**
2. **知识库审核**：审的是**团队预定义的题库 + rubric**，不是用户自定义内容。`draft`（草稿）默认不选来考学生，人工审核通过变 `reviewed` 才正式可用。
3. **用户自定义练习内容**：**第一版不做**，第二版才加入，届时引入 RAG（向量检索 + 现场生成题目）。第一版只做「封闭题库 + 有限关键词检索」。
4. **游戏化数值系统（XP/金币/等级）—— 要做真，但走轻量版**：
   - 后端为用户建轻量数值模型（`xp` / `coins` / `level`），随练习**真实增减、登录持久化**，不是写死的装饰。
   - 涨扣规则保持简单（见第 7 节），避免重数值设计。
   - **虚拟人物「小狐」仍是人格化包装**，其表情由真实面试评分（Evaluation）驱动，不存独立数据。
   - 用户重新登录后金币/等级/经验**不丢失**，持久化到数据库。

## 3. 分端改动清单

### 3.1 Agent 同学（改动很少）

Agent 的离线智能逻辑（选题、追问、评分、反思、评测、记忆）**已经完整且离线验证过**，核心**不用改**。只需配合 4 点：

| # | 改动点 | 说明 | 工作量 |
|---|--------|------|--------|
| 1 | **监控指标可被 API 查询** | 确认 `skillCoverage / repeatRate / planAdherence / longestSkillRun`（`reflectSession` 输出）能否被 API 拿到，或补一个「指标快照」宿主函数。 | 小 |
| 2 | **finish → RSI → 候选 链路贯通** | 确认「正常结束面试」的收尾 → 触发反思 → 产出候选策略，能否被 API 编排调用。 | 小 |
| 3 | **评测函数权限边界** | `evaluatePolicyCandidate` / `experiment-registry` 继续**只允许 API 宿主调用**，Agent 不做管理员认证。认证全在 API 层。 | 极小（不改）|
| 4 | **审核决定的写入** | `reviews.json` 审核账本的**写操作由 API 落库**，Agent 只负责复用 `buildKnowledgeCatalog` 的闸门逻辑重算 `reviewed` 状态。 | 极小 |

### 3.2 API 同学（改动很大，是主力）

#### A. 通用底座（最先做，阻塞一切）
- 认证：`POST /v1/auth/login`、`refresh`、`logout`，token 带 role scope（student/admin）。
- 数据库持久化：把所有 `uncommitted-*` 结果（turn/report/memory/experiment）真正落库，事务 + CAS。
- 把 `uncommitted-*` 变成 `committed`：验证归属 → 持久化 → 幂等 → CAS 提交。

#### B. 用户端接口（实现目前 501 的清单）
- `POST /v1/interviews`（创建面试 + 初始规划）
- `GET /v1/interviews` / `GET /v1/interviews/{id}`（列表 / 快照）
- `POST /v1/interviews/{id}/answers`（幂等提交回答）
- `GET /v1/interviews/{id}/report`（报告，含 reportId 分配、保存、鉴权）
- `GET /v1/runs/{id}` / `GET /v1/runs/{id}/events`（快照 + SSE，**SSE 的 Last-Event-ID 持久化**）
- `POST /v1/runs/{id}/cancellation`（取消）
- `GET /v1/profiles/me`（画像）
- **新增** `POST /v1/interviews/{id}/finish`（正常结束面试，触发收尾 + RSI）

#### C. 用户端「语音 + 学习复测」接口（api.md 标注「待设计」，前端已画交互）
- 音频上传 + ASR 转写触发、转写结果获取、转写确认提交
- `GET /v1/learning/resources`（资源列表）
- `POST /v1/learning/{id}/progress`（学习完成记录，区分「自报」和「可核实证据」）
- 复测触发接口

#### D. 管理端（三中台）接口 —— 几乎全新增

| 中台 | 新增接口 |
|------|---------|
| 监控中台 | `GET /v1/admin/metrics`（行为指标 + 运行状态）、`GET /v1/admin/feedback`（学生反馈）、告警流（SSE 或轮询）|
| 数据中台 | 知识库 CRUD、`POST /v1/admin/knowledge/{id}/review`（审核决定）、评测集/数据资产查询、分组隔离管理 |
| 评测中台 | `POST /v1/experiments`（创建）、`GET /v1/experiments`（列表，admin 权限）、`POST /v1/experiments/{id}/approve`（审核）、`POST /v1/experiments/{id}/rollback`（回退）、实验详情/逐例结果 |
| 审计日志 | `GET /v1/admin/audit` |

#### E. 权限与归属（贯穿所有）
- 学生接口：验证 `interviewId/runId/profile` 属于本人。
- 管理端接口：全部 `admin` scope 鉴权。

#### F. 游戏化数值系统（见第 7 节）
- 用户表加 `xp` / `level` / `coins` 字段。
- 涨扣规则集中配置，由「完成面试 / 完成学习 / 使用道具」等业务动作同步触发，不暴露独立加金币接口。

## 5. 需要代码实现的同学注意

- **文档读取契约**：`docs/prd.md`（需求）、`docs/api.md`（接口）、`docs/architecture.md`（架构）、`docs/collaboration.md`（协作）为真值。
- **Agent 契约文档**：`docs/agent-client.md`、`docs/agent-reflection.md`、`docs/evaluation-plan.md`、`docs/data-sources.md`、`docs/knowledge-curation.md` 等已冻结，Agent 侧能力以这些为准。
- **改接口前先动 `packages/contracts`**，再跑 `bun run openapi:generate` + `openapi:lint`，不要手改生成后的 YAML/JSON。
- **状态机**：Interview = `planning/awaiting_answer/processing_answer/completed/cancelled/failed`；Run = `queued/running/completed/failed/cancelled`。
- **renderer 不接收 rubric/source**：面试页只展示题目正文，评分规则和知识来源留在服务端。
- **诊断面板不展示推理链**：只展示状态摘要、选题理由、工具回执。

## 7. 游戏化数值系统需求（轻量版）

> 定位：让游戏感「真实可攒」，但**不做重数值设计**。核心是「完成练习 → 获得反馈 → 数字变化」的即时正反馈。

### 7.1 数据模型

用户表新增三个字段（轻量，无需独立表）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `xp` | integer | 累计经验值 |
| `level` | integer | 等级（由 xp 折算，或独立维护）|
| `coins` | integer | 金币余额 |

### 7.2 涨扣规则（初版默认值，可后续调参）

| 行为 | 变化 |
|------|------|
| 完成一场面试 | `xp +100` |
| 完成一次学习资源 | `xp +30`、`coins +20` |
| 完成一次复测 | `xp +100`、`coins +50` |
| 使用「请求提示」道具 | `coins -1` |

> 等级由 xp 折算：每 `500` xp 升 1 级（`level = floor(xp / 500) + 1`）。
> 上述数值均为**初版默认值**，后端集中配置在一个常量/配置处，方便后续调参，不要在业务逻辑里散落硬编码。

### 7.3 接口

- `GET /v1/profiles/me` 的返回里带上 `xp` / `level` / `coins`。
- 涨扣由「完成面试 / 完成学习 / 使用道具」等既有业务动作**同步触发**，不单独暴露「加金币」接口（避免刷分）。

### 7.4 明确边界（防止过度设计）

- **不做**：商城、道具购买、排行榜、签到、每日任务等复杂游戏系统。
- **只做**：数字随练习真实增减 + 登录持久化 + 界面即时反馈。
- 小狐表情**不存数据**，由真实评分驱动。
