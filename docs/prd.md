# 需求文档（PRD）

版本：0.1。目标交付：2026-12-19。适用范围：Java 后端、Web 前端两个岗位；Windows 10/11 x64 桌面客户端；联网使用统一服务器。

本文定义要交付的产品。除“当前实现状态”明确列出的基础能力外，下文均是待实现的目标需求。

## 1. 产品目标与用户

面向计算机相关专业学生，提供可反复练习的 AI 面试教练。学生通过岗位化面试发现技术和表达短板，经练习与复测看到变化；系统依据历次评估和后续表现改进追问策略。

| 用户 | 主要任务 |
| --- | --- |
| 学生 | 选择岗位、参加面试、查看报告、完成学习计划、复测、查看成长 |
| 管理员/团队 | 维护岗位知识和评分标准、检查工具与评测结果、审计/回退策略 |

产品成功需要同时证明“学生练习有针对性”和“系统策略可度量地改进”，不能只凭聊天流畅或学生分数上涨判断。

## 2. 用户流程与页面

1. 选择岗位、练习目标和时长（初始 15—25 分钟），读取历史画像并生成计划。
2. AI 提问；学生以文字或语音作答。语音先转写并允许确认，再提交内容分析。
3. 每轮更新技能状态，决定深挖、换技能、调整难度或收尾；界面反馈处理状态与剩余时间。
4. 面试结束生成技术/表达报告、证据、具体练习建议与资源。
5. 学习后以同技能不同题复测；查看能力变化和下一步计划。
6. 后台自动反思并形成策略实验，展示调整原因、参数变化和新旧指标。

| 页面 | 必须具备的交互 |
| --- | --- |
| 岗位与目标 | 两岗说明、目标/时长选择、开始面试、历史画像提示 |
| 面试 | 多轮问题、文字/录音输入、转写确认、进度/计时、取消、失败恢复提示 |
| 报告 | 多维评分、回答/音频证据、亮点不足、可执行建议、练习入口 |
| 学习与复测 | 资源及理由、完成状态、针对性复测、关联历史结果 |
| 成长记录 | 按岗位/技能展示历史变化、样本和策略版本 |
| 策略实验（管理） | 基线/候选差异、评测样本与结果、启用记录、回退 |

问题语音播报（TTS）作为首版体验目标；实时双向语音打断不列必交。诊断面板仅按需展示状态摘要、选题理由和工具回执，不能展示模型内部推理链。

## 3. 功能需求与验收

下列编号沿用赛题技术要求，便于代码、PR 和验收记录共同引用。

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| 1a | 双岗位、四类题 | Java/Web 各覆盖技术知识、项目深挖、场景、行为题；题目/rubric 明显不同 |
| 1b | 岗位知识源 | 技能、考点、优秀回答、追问模板、评分锚点有来源和版本 |
| 1c | Agent 自主知识访问 | 展示模型选择工具、实际查询及结果用于追问/评分的完整轨迹 |
| 1d | 知识访问质量 | 岗位/技能过滤、Top-K 和上下文预算有效；空结果不跨岗编造 |
| 2a | 语音与文本输入 | Windows 客户端完成两种输入；ASR 原文和确认文可关联 |
| 2b | 规划驱动追问 | 最后一轮相同、改变历史状态，下一步选择有合理差异 |
| 2c | 节奏与难度 | 管理剩余时间、覆盖和追问深度；连续失败可降难度，接近结束能收尾 |
| 3a | 状态感知规划 | 持续维护技能掌握度和置信度；未知/薄弱状态有不同决策依据 |
| 3b | 跨会话记忆 | 重启再练可调用旧薄弱点、已练题和能力变化，避免只重复原题 |
| 3c | 真实工具 | 至少一种工具有实际执行、授权参数和回执，不能是模型虚构结果 |
| 3d | 自动反思 | 面试后生成基于证据的复盘，后续表现到达后能影响策略候选 |
| 4a | 内容评估 | 正确性、知识深度、逻辑、岗位匹配均有量化分和回答依据 |
| 4b | 表达评估 | 真实 ASR＋语音/情感分析；语速、清晰度估计与自信表达有可说明的依据 |
| 4c | 综合报告 | 结构化分数、亮点不足和具体改进动作完整，信息不足可不评分 |
| 5a | 偏差驱动调整 | 原评估与符合条件的后续表现可配对；自动生成/评测/启用受限策略 |
| 5b | 系统改进指标 | 展示至少一轮真实新旧对比、分子分母与样本；没有改善不能标成功 |
| 5c | 可解释进化 | 可追溯调整什么、为什么、指标如何变化，以及失败/回退记录 |
| 6a | 个性化路径 | 薄弱技能关联有效资源、可执行练习和复测；点击不冒充完成 |
| 6b | 学生成长 | 两场以上记录按技能可视化，注明岗位、难度与评分/策略版本 |
| 6c | 系统进化曲线 | 系统指标与学生成绩分开绘制，显示样本量和实验版本 |
| 7a | 大模型核心能力 | 至少一个真实 LLM 用于理解、决策和报告；离线 fixture 不算在线验收 |
| 7b | 多模态综合分析 | 实际音频进入 ASR/声学/情感分支，内容与表达共同进入报告 |
| 7c | 岗位针对性 | 两岗场景与评分锚点不同，不仅替换岗位标题 |
| 7d | 实用与创新 | 非开发机可安装操作；Agent/RSI 和异常流程真实可运行 |

每岗初始目标约 6 个技能模块、40 道题（四类各 10）；这是团队内容目标，不是赛题硬性数量。当前各 4 条草案远未达到该目标。

## 4. 两岗差异

| 岗位 | 技能范围 | 场景与评分侧重示例 |
| --- | --- | --- |
| Java 后端 | Java/JVM、并发、Spring/事务、数据库、缓存/分布式、项目设计 | 订单与缓存一致性：事务边界、并发不变量、失败恢复和取舍 |
| Web 前端 | JS/TS、浏览器/网络、React、异步/状态、性能/可访问性、项目设计 | 搜索响应竞态：过期结果、取消、组件生命周期和交互状态 |

共用“正确性/深度/逻辑”等维度，但知识包、锚点和权重独立版本化。所有题目及优秀回答需岗位审核，draft 不能称作正式题库。

## 5. 双闭环与评估边界

学生：练习 → 多维反馈 → 资源与练习计划 → 不同题复测 → 成长记录。

系统：面试反思 → 收集后续表现 → 合格偏差配对 → 自动候选 → 自动评测 → 实验范围自动启用 → 对照与回退。首版固定评分 rubric，优先调整追问策略；不能以人工改提示词替代自动链路。

当前能力估计、指定学习条件下的复测预测、实际学习增益分别记录。自动门槛使用预标注场景，真人效果另由独立审核评定。算法和数据划分见[架构](architecture.md)与[评测计划](evaluation-plan.md)。

表达分析不能把 ASR confidence 当成学生自信；情感结果是模型估计，不能证明真实心理状态。文字输入不补造语音维度，短音频/噪声等条件下允许“不足以评价”。

## 6. 非功能要求与范围

- 所有权：学生只能访问本人的会话、报告、画像和录音；管理操作单独授权。
- 一致性：重复提交不生成重复正式回答；取消或旧 attempt 结果不覆盖新状态。
- 恢复：断流可查询正式状态，重启后任务明确完成/失败/待恢复，不悄悄丢失。
- 成本：模型、工具和总时限有硬预算；重试统一管理并计入预算。
- 数据：原音频默认处理后删除，需听审时单独同意并限期保留；删除传播至画像/报告关联。
- 分发：Windows 10/11 x64，安装、启动、麦克风、连接失败提示及卸载均单独验收。

首版不含 Windows 外平台、摄像头情绪识别、实时全双工语音、任意代码执行、模型微调、多自主 Agent 服务或每台学生电脑上的本地服务器。

## 7. 评分依据与交付

| 维度 | 权重建议 | 核心证据 |
| --- | --- | --- |
| 岗位化题库与知识组织 | 12% | 两岗差异、知识质量、访问策略 |
| 多模态交互与对话 | 15% | 语音/文本、规划追问、节奏 |
| Agent 四项能力（含状态感知规划） | 32% | 规划、记忆、工具、反思实际链路 |
| 多维评估与报告 | 15% | 内容/表达证据和可执行建议 |
| RSI 自进化 | 16% | 指标、至少一轮对比、变更解释 |
| 实用性与创新性 | 10% | 界面、指导价值、可运行创新 |

Agent＋RSI 合计 48%，作为主要证据线；不按权重机械分配工时，也不删除低权重硬要求。最终交付安装包、源码、部署/使用说明、接口契约和实际评测报告。分工、里程碑与每周组会规则见[协作说明](collaboration.md)。
