# Agent 主流程演示与联调验收

这条离线场景把同一来源链上的规划、知识工具、失败恢复、跨会话记忆、反馈修订和收尾预览串起来。Java后端与Web前端各运行一遍，不需要密钥、麦克风或桌面客户端。它是工程联调验收，不是真实模型质量、真人学习效果或正式业务数据库验收。

## 队友复现入口

在仓库根目录、依赖已安装的环境运行：

```powershell
bun --no-env-file run agent:journey
bun --no-env-file run agent:journey --verify .cache/agent-journey/run-实际目录
```

Windows未将Bun加入PATH时，可把 `bun` 换为 `./node_modules/@oven/bun-windows-x64/bin/bun.exe`。两条命令都不加载 `.env`；不需要填写或发送任何密钥。

首条命令创建新的私有产物目录，启动仅绑定127.0.0.1随机端口的Agent HTTP/SSE服务并在结束后关闭。模型侧使用真实Pi SDK与禁止网络的固定provider，知识与评分工具执行现有代码。第二条命令只读产物并重验，不重跑provider、不自动重试原任务、不写正式数据。

## 场景步骤与证据

| 步骤 | 实际行为 | 验收依据 |
| --- | --- | --- |
| 首场创建与规划 | 两技能、两轮预算，SDK自主调用本地岗位知识工具 | workflow、lastPlan工具回执及运行事件 |
| 第一次回答失败 | 固定provider明确注入一次无效JSON | failed运行、MODEL_OUTPUT_INVALID、result=null |
| 显式恢复 | 保持原会话；重放旧失败run仍失败且不追加provider调用；用新run提交同一回答 | 失败前后快照、调用计数、失败/重试请求与会话中的run绑定 |
| 首场完成 | 两次成功评分后生成报告、反思和记忆候选 | 原始closeout及一致性重验 |
| 跨会话记忆 | 将首场记忆候选写文件，再读取并校验归属，作为第二场baseMemory | memory文件摘要、candidate/baseMemory相等、两条priorEvidence |
| 第二场规划 | 保留原技能并加入岗位特有技术技能，选择未见题并完成一轮 | 旧题排除、状态历史、知识工具回执与第二场记录 |
| 修订与预览 | 对第二场反馈追加一版，通过同一个HTTP/SSE服务生成只读预览 | 修订历史、预览来源、原报告分数/会话摘要不变、provider计数不变 |

每岗预期3个成功评分轮次、1个失败运行、2条召回观察；这些数值来自核验后的实际产物，不是人工填的成功标签。新增技术技能是显式控制输入，不能把选题变化解释为记忆单独造成的教学改进。

恢复指的是**同一会话在模型输出失败后显式重试业务命令**，不是HTTP自动退避、模型再次修复或服务器崩溃恢复。同run重放保持原结果，不把失败改成零分或成功。其他恢复场景仍由各自独立脚本验证，不能混进本场景的证据分母。

## 产物与独立校验

`.cache/agent-journey/run-*` 保存：

- `report.json`：固定文件摘要、生产者源码清单、离线模式和证据边界。
- `java-backend.case.json` / `web-frontend.case.json`：两场会话、失败/重试、版本链、预览、事件轨迹与本地provider计数。
- 对应 `*.memory.json`：主流程实际写入、读取的首场记忆候选。

文件包含合成原答与候选全文，按私有开发材料处理，不提交Git。内部服务token不写入产物。校验拒绝符号链接、超8MiB文件、非UTF-8、错误schema或摘要；只打开固定文件名。

独立校验会重验完成会话、评分/收尾一致性、记忆来源、失败/重试和关键事件绑定，重算修订预览，并重新计算所有检查。即使重新计算了文件和报告摘要，篡改分数或关键trace请求摘要仍会被领域校验拒绝。摘要与声明计数不是签名，不能认证实际网络执行、审核人或真实学生身份。

`sameSource` 表示产物源码清单与当前仓库是否一致；不一致不意味着当时执行的是当前代码。可重建历史结果只说明当前校验仍兼容，不能把它写成新的真实模型运行。输出始终 `qualityClaimEligible=false`、`humanReferenceCount=0`、`formalCommitted=false`。

## 接入真实业务前的替换点

场景驱动器用局部变量采用Agent会话候选，并采用首场记忆候选进入下一场；这是业务宿主的模拟，不是正式提交。业务API必须从可信存储加载身份/旧快照/记忆，使用既有任务归属、CAS和提交回执机制，不能照搬本地变量赋值为正式成功。

编辑者权限由运行服务的宿主回调注入，本例的synthetic编辑者只用于开发；不能当真实审批。预览结果不可正式提交，现有未实现业务接口仍返回501。外部客户端/桌面继续由队友负责。

## 验收覆盖表

| 覆盖 | 本条主流程是否证明 |
| --- | --- |
| 状态规划、真实本地知识工具、两场候选链、反馈版本与HTTP/SSE预览 | 是，限固定provider工程场景 |
| 文件记忆保存/重读、新进程只读校验 | 是；不等于正式数据库或运行进程崩溃恢复 |
| HTTP429、预算重试/输出修复 | 否；见 `agent:model:recovery:demo` 与[模型恢复](model-recovery.md) |
| SQLite重启、unknown对账 | 否；见 `agent:durable:demo` 与[持久恢复](durable-runtime.md) |
| 真实LLM、ASR/TTS、实体麦克风、学生或专家质量 | 否，需独立授权与相应验收材料 |
| 正式知识批准、真实RSI提升、生产部署 | 否 |

题目来自现有岗位种子资料，允许draft用于开发预览，不等于两岗全部知识内容已审核。课堂/组会可以展示本报告与故障分支，不能将合成评分当质量准确率。
